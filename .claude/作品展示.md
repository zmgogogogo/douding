一、产品概述
1.1 模块核心价值
瀑布流是拼豆首页的内容主载体，核心解决三大问题：
适配多样比例：拼豆模板 / 作品宽高比例差异大（方形、长条人像、横版场景），瀑布流无需强制裁剪图片，完整保留图案比例与视觉效果。
高信息密度：相比整齐网格，空间利用率提升 20% 以上，一屏展示更多内容，降低用户翻页成本。
沉浸式浏览：错落的视觉节奏配合无限下拉，符合用户 “刷内容” 的使用习惯，提升停留时长与创作转化率。
1.2 核心设计原则
性能第一原则：图片懒加载、虚拟滚动、离屏缓存多管齐下，保证数百条数据滑动依然 60 帧流畅，低端机不卡顿。
视觉一致性原则：卡片样式统一、间距规范、信息层级清晰，错落但不杂乱。
交互友好原则：点击反馈明确、加载状态可感知、异常状态有兜底、操作路径短。
可扩展原则：支持多种卡片类型、多种排序筛选、自定义列数与间距，适配不同业务场景。
弱网友好原则：骨架屏预占位、图片渐进式加载、失败可重试，弱网环境依然有良好体验。

2.2 瀑布流布局核心原理
采用「等宽列 + 最短列优先填充」的标准 Masonry 算法，是百度图片、小红书、Pinterest 通用的经典实现：
列宽计算：容器宽度减去左右边距与列间距，按当前列数等分，得到单卡片宽度。
高度自适应：卡片宽度固定，高度由图片比例 + 底部信息区自然撑开，不做强制裁剪。
填充规则：
第一行卡片依次填充每一列顶部。
从第 N+1 张开始，计算每一列的当前总高度，将新卡片放到高度最小的列的下方。
重复该逻辑，所有卡片依次向下排列。
容器高度：所有卡片渲染完成后，取最高列的高度作为容器总高度，撑开父容器。

4.3 核心算法实现
4.3.1 瀑布流布局核心逻辑
javascript
运行
// useWaterfallLayout.js 核心伪代码
import { ref, computed, onMounted, onUnmounted } from 'vue'

export function useWaterfallLayout(containerRef, options = {}) {
  const columnCount = ref(2)       // 当前列数
  const columnWidth = ref(0)       // 单列宽度
  const columnHeights = ref([])    // 每列当前高度
  const itemPositions = ref([])    // 每个卡片的left/top位置
  const gap = options.gap || 12
  const edgeGap = options.edgeGap || 16

  // 1. 计算列数与列宽
  function calcColumn() {
    const containerWidth = containerRef.value.clientWidth
    // 根据宽度匹配响应式断点
    if (containerWidth < 768) columnCount.value = 2
    else if (containerWidth < 1200) columnCount.value = 3
    else if (containerWidth < 1600) columnCount.value = 4
    else columnCount.value = 5

    // 计算单列宽度 = (总宽 - 边距 - 列间距) / 列数
    columnWidth.value = (containerWidth - edgeGap * 2 - gap * (columnCount.value - 1)) / columnCount.value
    // 初始化列高度数组
    columnHeights.value = new Array(columnCount.value).fill(0)
  }

  // 2. 计算单个卡片位置
  function calcItemPosition(index, itemHeight) {
    // 找到高度最小的列索引
    const minHeight = Math.min(...columnHeights.value)
    const minIndex = columnHeights.value.indexOf(minHeight)
    
    // 计算left和top
    const left = edgeGap + minIndex * (columnWidth.value + gap)
    const top = columnHeights.value[minIndex]
    
    // 更新该列高度
    columnHeights.value[minIndex] += itemHeight + gap
    
    return { left, top, width: columnWidth.value }
  }

  // 3. 批量计算所有卡片位置
  function layoutItems(items) {
    columnHeights.value = new Array(columnCount.value).fill(0)
    itemPositions.value = items.map((item, index) => {
      const imgHeight = columnWidth.value * (item.height / item.width) // 按图片比例算高度
      const infoHeight = 60 // 底部信息区固定高度
      const totalHeight = imgHeight + infoHeight
      return {
        ...calcItemPosition(index, totalHeight),
        height: totalHeight,
        index
      }
    })
  }

  // 4. 容器总高度
  const containerHeight = computed(() => Math.max(...columnHeights.value) + 'px')

  // 5. 窗口resize重新计算
  function handleResize() {
    calcColumn()
    layoutItems(currentItems.value)
  }

  onMounted(() => {
    calcColumn()
    window.addEventListener('resize', handleResize)
  })
  onUnmounted(() => {
    window.removeEventListener('resize', handleResize)
  })

  return {
    columnCount,
    columnWidth,
    itemPositions,
    containerHeight,
    calcColumn,
    layoutItems
  }
}

// useLazyLoad.js
export function useLazyLoad(rootRef) {
  let observer = null

  function observe(el, src) {
    if (!observer) {
      observer = new IntersectionObserver((entries) => {
        entries.forEach(entry => {
          if (entry.isIntersecting) {
            // 进入可视区，加载图片
            const img = entry.target
            img.src = src
            img.classList.add('loaded')
            observer.unobserve(img)
          }
        })
      }, { root: rootRef.value, rootMargin: '200px' })
    }
    observer.observe(el)
  }

  function unobserve(el) {
    observer?.unobserve(el)
  }

  return { observe, unobserve }
}

// useInfiniteScroll.js
export function useInfiniteScroll(containerRef, callback) {
  const loading = ref(false)
  const finished = ref(false)

  function handleScroll() {
    if (loading.value || finished.value) return
    
    const container = containerRef.value
    const scrollBottom = container.scrollTop + container.clientHeight
    const threshold = 200
    
    if (container.scrollHeight - scrollBottom < threshold) {
      loading.value = true
      callback().finally(() => {
        loading.value = false
      })
    }
  }

  onMounted(() => {
    containerRef.value.addEventListener('scroll', handleScroll)
  })
  onUnmounted(() => {
    containerRef.value?.removeEventListener('scroll', handleScroll)
  })

  return { loading, finished, handleScroll }
}
4.4 性能优化方案
4.4.1 虚拟滚动（大数据量必备）
当数据超过 100 条后，开启虚拟滚动，只渲染可视区域的卡片，大幅减少 DOM 节点数，保证千条数据依然流畅：
计算可视区域上下边界，只渲染范围内的卡片。
用空白占位撑起滚动高度，避免滚动条跳动。
卡片离开可视区后销毁 DOM，进入可视区再创建。
缓冲区：可视区上下各多渲染 200px，快速滚动时避免白屏。
4.4.2 图片性能优化
尺寸适配：根据屏幕宽度请求对应分辨率图片，避免加载大图浪费流量。
格式优化：优先加载 WebP 格式，体积减少 30%。
占位优化：首屏用低质量占位图，提升首屏感知速度。
缓存复用：图片浏览器缓存 + 内存缓存，返回列表不用重新加载。
4.4.3 渲染优化
v-for key 优化：使用唯一 ID 作为 key，不使用 index，保证列表更新时 DOM 复用率最高。
组件懒加载：卡片组件按需引入，非首屏内容延迟渲染。
防抖节流：滚动事件节流，resize 事件防抖，避免高频触发计算。
离屏预计算：新数据在 Web Worker 中计算位置，不阻塞主线程。

六、异常与边界处理
6.1 数据异常
空数据：分类下无内容时，展示空状态插画 + 「暂无内容，去看看其他分类吧」提示。
搜索无结果：展示「未找到相关内容，换个关键词试试」。
数据加载失败：
首屏失败：显示错误页 + 「点击重试」按钮。
加载更多失败：底部提示「加载失败，点击重试」，不影响已加载内容。
图片加载失败：显示灰色默认占位图，带图片图标，不影响整体布局。
6.2 网络异常
弱网环境：延长超时时间，显示加载中提示。
断网状态：读取本地缓存数据展示，提示「当前网络不佳，已加载缓存内容」。
请求失败自动重试 1 次，仍失败再提示用户。
6.3 边界场景
单条数据：正常靠左排列，不强行拉伸。
超高 / 超宽图片：限制最大高度比例，避免单张卡片过长 / 过宽破坏布局。
文字过长：标题最多两行，超出省略号截断。
数字过大：超过 1 万显示「1.2w」格式，超过 100 万显示「125.6w」。
快速切换分类：取消上一个未完成的请求，避免数据错乱。

附录 B：常见问题与解决方案
图片加载完布局跳动：提前获取图片宽高比例，渲染前就计算好卡片高度，图片加载不改变高度。
resize 后位置错乱：防抖处理 resize，重新计算所有卡片位置，一次性更新。
快速滚动白屏：增加缓冲区，提前渲染上下区域，优化图片加载速度。
Safari 滚动卡顿：添加 -webkit-overflow-scrolling: touch，开启硬件加速。
