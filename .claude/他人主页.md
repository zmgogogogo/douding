一、文档概述
1.1 页面核心定位
访客视角（查看别人主页）：展示创作者基础资料、社交数据、全部原创 / 二创拼豆作品、收藏、获赞数据；支持关注、私信、举报、拉黑。
本人视角（进入自己主页）：额外开放资料编辑、作品管理、订单、豆子库存、收益、草稿、消息中心入口，等同于个人中心主页。
业务价值：创作者人设展示、粉丝沉淀、作品曝光引流，串联「作品→作者主页→关注→查看更多作品」核心流量闭环。
1.2 路由定义
公共访问：/user/profile/:uid（uid 为目标用户唯一 ID）
快捷跳转：点击作品页作者头像 / 昵称、评论区用户头像、@用户跳转至该页面
本人主页快捷路由：/mine，自动填充当前登录用户 uid
1.3 全局 UI 基础规范（沿用项目统一设计规范）
主色：品牌蓝#2b54c9；点赞红色#f53f3f；中性灰：#333/#666/#999/#eee/#f7f8fa
圆角：头部卡片 16px、内容卡片 12px、标签 10px、按钮 8px
间距：模块间距 24px、卡片内边距 16px、元素基础间距 8px/12px
布局模式：PC 端左右分区；移动端上下流式自适应布局。
1.4 技术栈统一约定
表格
端	技术选型
Web 前端	Vue3 + TypeScript + Element Plus、Pinia 状态管理、图片懒加载
后端	SpringBoot 2.7、MyBatis-Plus、MySQL8.0、Redis6.x
文件存储	MinIO：头像、主页背景图、作品封面、资质认证图片
部署	Nginx 反向代理、HTTPS、CDN 加速静态资源、Redis 热点数据缓存

三、各模块详细需求、UI、交互逻辑
模块 1：头部 Banner 个人信息卡片（最高优先级展示区）
3.1 展示元素明细
背景封面图
用户自定义上传背景图，无自定义则使用系统默认拼豆风格背景；
图片尺寸建议：1920×400，自动裁切居中铺满，高斯虚化底层。
用户头像
圆形裁剪；点击头像弹出大图预览；本人可唤起更换头像弹窗；
基础身份信息
昵称、专属 UID、达人认证标（拼豆达人 / 优质创作者官方标识）、VIP 会员标识；
个性签名简介（最多 120 字）；
四大核心数据统计
表格
数据项	含义
作品	用户发布上线的有效拼豆作品总数（剔除下架、删除）
粉丝	关注该用户的总人数
关注	该用户关注其他创作者数量
获赞	全部作品累计点赞总和
交互：点击数字可跳转对应粉丝列表、关注列表弹窗 / 新页面；
属性标签组
入驻时长、擅长色系（MARD 色系、立体拼豆、平面像素画）、难度偏好、所在地区；
操作按钮组（区分本人 / 访客）
场景 A：访问他人主页（访客）
按钮 1：【关注】/【已关注】；
按钮 2：【发私信】；
更多下拉：拉黑用户、举报主页（违规内容、盗图、骚扰等）；
场景 B：访问自己主页
主按钮：【编辑资料】，跳转个人资料编辑弹窗；
快捷入口：我的订单、豆子仓库、草稿箱、收益中心。
3.2 交互细则
关注逻辑：未关注→点击发起关注接口；成功按钮切换「已关注」；再次点击取消关注；未登录点击唤起登录弹窗；
私信：未登录跳转登录；已登录打开私信对话窗口；
拉黑：拉黑后不再接收该用户私信、评论、@提醒，主页默认不可浏览；
数据 hover：hover 作品 / 粉丝数字展示简要提示文案。
模块 2：Tab 标签切换导航栏
2.1 Tab 菜单固定 5 项
全部作品（默认）：用户所有已上架公开拼豆作品，按发布时间倒序；
收藏：该用户收藏的其他作者拼豆图纸；
获赞：该用户所有被点赞的作品明细；
拼豆教程：用户发布的图文 / 视频拼豆制作教程；
动态：用户日常制作打卡、碎碎念动态；
2.2 交互规则
Tab 切换时加载对应分页数据，切换时展示骨架屏加载；
当前选中 Tab 下划线高亮；移动端 Tab 横向可左右滑动；
无数据时展示空状态占位图 + 提示文案（例：暂无作品、还未收藏任何图纸）。
模块 3：Tab 内容渲染区（作品卡片复用现有作品卡片组件）
3.1 作品卡片复用规则
沿用作品详情页同款卡片：封面图、标题、浏览量、点赞、标签；点击卡片直接跳转对应作品详情页；
3.2 加载策略
分页懒加载：PC 端每页 12 张；移动端每页 6 张；滚动触底自动加载下一页；
排序规则：默认发布时间从新到旧；支持下拉筛选：最多点赞、最多浏览、最新发布；
3.3 本人专属操作（仅自己主页可见）
作品卡片右上角展示：编辑作品、下架作品、删除作品、置顶代表作按钮。
模块 4：PC 端右侧侧边固定栏
完整个人简介卡片：展示完整版自我介绍、创作风格、入坑时长；
豆子仓库概览：常用色系、累计消耗豆子总数、仓库余量统计；
代表作精选：用户手动设置 3 张置顶优质作品；
相似创作者推荐：基于标签、色系推荐同类型拼豆作者；
关注快速入口：查看 TA 的关注列表。
模块 5：评论与 @联动附属逻辑（关联原有评论体系）
在任意作品评论区点击用户头像，直接进入该用户主页；
评论内 @用户昵称，点击跳转主页；
主页内新增「@我的」消息入口（本人视图）。
模块 6：空状态兜底页面
用户从未发布作品：「还没有发布拼豆作品，敬请期待～」；
无收藏：「还没有收藏心仪的拼豆图纸」；
账号被封禁 / 注销：页面提示「该账号已封禁 / 不存在」；
访问被拉黑用户主页：无权限访问提示。

4.2 script 逻辑精简
typescript
运行
import { ref, computed, onMounted } from 'vue'
import { useRoute } from 'vue-router'
import WorkCard from '@/components/WorkCard.vue'
import { getUserProfileApi, toggleFollowApi, getUserWorkListApi } from '@/api/user'

const route = useRoute()
const targetUid = route.params.uid as string
const loginUid = ref(Pinia.user.uid)
const isSelf = computed(() => loginUid.value === targetUid)

// 基础数据
const userInfo = ref({})
const statData = ref({
  workCount: 0,
  fansCount: 0,
  followCount: 0,
  totalLike: 0
})
const isFollow = ref(false)
const activeTab = ref('work')
const workList = ref([])
const page = ref(1)
const pageSize = ref(12)
const hasMore = ref(true)

// 初始化加载主页数据
const initPage = async () => {
  const res = await getUserProfileApi(targetUid)
  userInfo.value = res.data.userInfo
  statData.value = res.data.stat
  isFollow.value = res.data.isFollow
}

// 关注/取消关注
const handleFollow = async () => {
  if (!loginUid.value) {
    // 唤起登录弹窗
    return
  }
  await toggleFollowApi({ targetUid })
  isFollow.value = !isFollow.value
  statData.value.fansCount += isFollow.value ? 1 : -1
}

// Tab切换加载数据
const onTabChange = () => {
  page.value = 1
  workList.value = []
  loadMoreData()
}
const loadMoreData = async () => {
  const res = await getUserWorkListApi({
    uid: targetUid,
    tab: activeTab.value,
    page: page.value++,
    pageSize: pageSize.value
  })
  workList.value.push(...res.data.list)
  hasMore.value = res.data.total > workList.value.length
}

onMounted(() => {
  initPage()
  loadMoreData()
})

七、Redis 缓存设计（优化页面访问性能）
7.1 缓存 Key 设计规范
用户主页基础信息：user:profile:{uid} 有效期 2 小时；
用户关注状态：user:follow:uid:{loginUid}:target:{targetUid}；
统计数据缓存：user:stat:{uid}（作品、粉丝、获赞），定时任务每 30 分钟同步数据库；
粉丝 / 关注列表热点缓存；
防刷限流：关注、私信、举报接口单账号 1 分钟限制 5 次。
7.2 缓存更新策略
用户修改资料、新增作品、新增关注后主动清除对应 key 缓存；
定时任务兜底刷新统计数据。
八、权限与身份校验核心逻辑
8.1 三种访问身份
未登录游客
仅可浏览主页、作品；关注、私信、收藏、评论全部唤起登录弹窗；
已登录普通访客
正常关注、私信、举报、收藏；无法编辑对方资料；被拉黑则禁止访问；
本人登录账号
开放资料编辑、作品管理、库存、订单、收益等全部后台管理入口；
8.2 拉黑权限控制
A 拉黑 B：
B 无法打开 A 的用户主页；
B 无法给 A 发私信、评论 A 作品、@A；
A 不会收到 B 任何互动消息；
8.3 封禁账号处理
账号 status=0 封禁：访问主页提示「账号已被限制访问」，所有作品对外隐藏。
九、安全防护、异常兜底、前端兼容适配
9.1 安全策略
XSS 防护：前端渲染简介、动态内容转义特殊字符；后端过滤 HTML 恶意标签；
SQL 注入：MyBatis 参数化查询，禁止拼接 SQL；
图片校验：头像、背景图上传校验格式（jpg/png/webp）、大小限制，防盗链；
敏感词过滤：个性签名、动态、私信、评论接入敏感词库，违规直接驳回；
接口限流：关注、私信、举报高频操作限流防刷。
9.2 前端异常兜底
头像、背景图加载失败：替换系统默认占位图；
接口超时 / 500 错误：展示「加载失败，点击重试」按钮；
uid 不存在：页面跳转 404 页面；
数据空值兜底：简介为空显示默认文案；
9.3 多端适配规则
PC 端：双栏布局，侧边栏固定悬浮；
平板：侧边栏下移至底部；
手机端：Tab 吸顶、作品卡片双列网格、按钮点击区域≥44px；
适配主流浏览器：Chrome、Edge、Firefox；小程序端 Uniapp 复用同一套业务逻辑。
